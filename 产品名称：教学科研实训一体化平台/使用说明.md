# 教学科研实训一体化平台 · Demo 工程使用说明

> 本文档面向需要接手、阅读或继续扩展本 Demo 的同事，帮你在 10 分钟内搞清楚"这个工程是什么、为什么这么设计、怎么用"。

---

## 1. 工程是什么

一个为了**演示产品理念**而制作的前端 Demo 资产集，**不含任何可运行服务**。它由两件东西组成：

1. **一份页面设计文档** — 讲清楚产品每一页长什么样、每个区域是干嘛的、数据从哪来。
2. **一套 TypeScript 假数据** — 围绕一条主故事线精心编排，覆盖 20 个页面所需的全部展示内容。

页面开发只需 `import { ... } from './mock-data'`，就能拿到完整的、前后关联一致的演示数据，免去现编数据的痛苦。

## 5. 页面文档怎么用

`页面设计文档.md` 是唯一的页面真源，结构固定：

```
0  全局说明                      （产品定位 · 布局 · 公共组件 · 动线图）
1  智慧教学模块（1.1 ~ 1.12）      12 个页面
2  专业知识引擎模块（2.1 ~ 2.8）   8 个页面
3  页面 × 假数据映射表            一行一页，标清用到哪些 mock 变量
4  主故事线演示动线剧本           给讲解人用
```

**每个页面的写法统一为 5 段**：

1. 页面目的
2. 进入路径
3. 布局示意（ASCII 画）
4. 关键组件/按钮
5. 状态变体（空 / 正常 / 异常）
6. 使用的假数据（会直接点名变量，如 `classProfiles` / `teachingPlans`）

**页面开发的推荐工作流**：

1. 打开 `页面设计文档.md` 找到你要做的页面（如 1.4 教学设计工作台）。
2. 看"使用的假数据"那一行，知道要 `import` 哪些变量。
3. 按 ASCII 布局 + 组件清单实现 UI。
4. 状态变体用文档里列举的场景切数据即可（如 2302 班对照态用 `hw-m-003-2302`）。

## 7. 扩展 / 修改指南

### 7.1 加一个学生

1. 去 `students.ts` 追加一条 `Student`（注意 `classId` 要存在）。
2. 可选：去 `studentProfiles.ts` 加对应画像（不加也不会报错，仅列表页少一张画像卡）。

### 7.2 加一条资源

1. 去 `resources.ts` 追加 `Resource`。
2. 关键字段：`knowledgeNodeIds`（多对多）、`courseIds`。
3. 节点 ID / 课程 ID 必须在 `graphNodes` / `courses` 里已经存在。

### 7.3 加一个图谱节点

**旧单层引擎（兼容）**：继续维护 `knowledgeGraph.ts` 时：

1. 在对应 `mechNodes` / `lawNodes` / `nurseNodes` 数组末尾追加。
2. 如有关系，再在对应 `*Edges` 数组里追加 `GraphEdge`。
3. ID 遵守 §4.3 的 `kn-mech-*` / `sk-mech-*` / `core-mech-*` 等前缀。

**三层模型 · L3 教学单元点**：新增强烈建议写在 `kgL3.ts`（类型 `L3Node`），补齐 `kind`、`teachingActivities`、`textbookAnchors`，并在 `kgBridges.ts` 的 `l2ToL3Bridges` 中挂上对应 L2 计划或小节；若仅维护旧 `graphNodes` 将无法在 2.1 三层画布与按桥推导的联动中出现。

### 7.4 加一次作业 / 考试评价

1. 在 `homeworks.ts` / `exams.ts` 追加新项（类型为 `HomeworkEvalInput` / `ExamEvalInput`：不含 `studentResults` 字段即可）。
2. 导出时由 `evalResultBuilders.ts` 的 `withHomeworkStudentResults` / `withExamStudentResults` 自动补齐 `studentResults`（与汇总字段在 Demo 级大致对齐的逐人逐题假数据）。考试若需题目行筛选，为该项填写 `questionAccuracy` 数组；未开考的考试可留空分桶与 `questionAccuracy`。
3. 必填："分数分布 + 热点错题 + 重点学生 + AI 洞察"四段式。
4. 热点错题里的 `knowledgeNodeId` 建议填实际存在的节点 ID，方便跳转资源库联动。

### 7.5 新增一个完整教学设计

主线焦点小节 `sec-3-2` 有三个设计样本（讲义 / 课堂 / 作业）可以作为模板复制：

- `design-sec-3-2-handout`
- `design-sec-3-2-class`
- `design-sec-3-2-homework`

模仿它们的 `chatHistory` 和 `outputs` 写新的即可。

### 7.6 扩展图谱或新增课程方向（旧版图谱）

1. 在 `knowledgeGraph.ts` 的 `mechNodes` / `mechEdges` 中追加节点与边，保持 `prof-mech`。
2. 在 `courses.ts` / `subjects.ts` 挂上对应课程与知识点 ID。
3. 节点数建议 ≥ 20，否则图形态过稀疏。

### 7.7 新增一份 L2 标准课程计划

1. 在 `kgLegacyCoursePlans.ts` 追加一条 `LegacyCoursePlanMeta`（课程名/学时/学分/教材）。
2. 在 `kgL2.ts` 追加一条 `L2StandardCoursePlan`（`chapters` 按章-节结构填写，`importedFromLegacyMetaId` 指向第1步新建的 ID，`derivedFromL1NodeIds` 指向相关 L1 节点）。
3. 在 `kgBridges.ts` 追加对应的 `L1ToL2Bridge`（`l1NodeId` 指向能力/课程标准，`l2PlanIds` 包含新 ID）。

### 7.8 新增一对 L2→L3 桥

1. 确认 `l2PlanId` 和 `l3NodeIds` 中的所有 ID 已在 `kgL2.ts` / `kgL3.ts` 中存在。
2. 在 `kgBridges.ts` 的 `l2ToL3Bridges` 数组末尾追加 `L2ToL3Bridge`。
3. 若按小节粒度，`container` 填 `{ kind: "section", l2PlanId: "...", sectionId: "..." }`，sectionId 必须在对应计划的 chapters 中存在。

### 7.9 为 L3 节点新增教学活动

1. 在 `kgL3.ts` 找到目标节点，在 `teachingActivities` 数组末尾追加 `TeachingActivity`。
2. 字段：`mode`（从 `TeachingActivityMode` 联合类型中选一个）/ `description` / `estimatedMinutes`（可选）/ `sampleResourceIds`（可选，指向 `resources.ts` 中的资源 ID）。
3. 教学活动会在 2.6 资源详情页和 2.8 实训详情页的"L3 节点展开"中显示。

## 8. 注意事项

1. **这只是 Demo 数据**，不要把它直接对接到真实 API。真实对接时用它来做接口形状的参考，然后从 `types.ts` 抽类型。
2. **所有时间戳都以 2026 春季为基准**。想展示不同时间点时，对应地修改 `createdAt` / `plannedDate` 等字段即可。
3. **图片 / 文件 URL 都是占位字符串**（如 `/covers/course-mech-draw.jpg`）。接入时请替换为真实 CDN 或本地资源路径。
4. **教学设计的产物（`outputs`）也是展示用的元数据**，并非真的 PDF/视频文件。
5. **人设提示词、AI 洞察文案、策略模板** 都是手写的 mock 文案，真实产品里应由 LLM 实时生成。
6. **机制 2302 班刻意设计成两极分化**（σ=15.2），用于展示异常洞察能力。相关 AI 洞察文字和重点学生数据都围绕这个设定展开，改动时需要同步调整。
